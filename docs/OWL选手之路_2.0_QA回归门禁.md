# OWL选手之路 · QA 回归门禁

> 当前维护目标：**2.0 Alpha 1 · Batch2**
>
> 这是项目的“发布门禁文档”。  
> 核心原则：**旧版本 PASS 只能作为历史基线，不能替代当前版本重新回归。**
>
> 历史上已经有过 15 赛季长档、世界杯完整路线、390px 手机端、潜力、合同、轮换、存档迁移等大量自动回归；2.0 Alpha 1 也曾达到过完整权威 QA 基线。  
> 但任何底层逻辑变化后，都必须重新验证受影响路径，禁止拿旧绿灯给新版本背书。

---

# 0. QA 等级定义

## 0.1 当前执行对象

- 当前 QA 对象是拆分后的 `dev-public/dev/` 网页，不再以历史打包 HTML 作为唯一测试对象。
- 本地静态检查覆盖 `dev-public/dev/src/**/*.js`；线上验收覆盖 `https://owl-game.painkiller.eu.org/dev/` 的实际资源。
- 发布前必须确认 GitHub `dev` 的提交与本地候选版本一致，再确认 Cloudflare dev 页面返回的是同一份资源。
- `Archive/` 是本地归档目录，不属于测试输入，也不应上传到 GitHub。

## P0 · Release Blocker
出现任意一个，禁止公开发布：

- 无法新建职业生涯
- 无法继续比赛
- 卡死 / 无限循环
- 存档无法读取
- 读档数据严重错乱
- 比赛胜负与晋级方向相反
- 赛季无法结束
- 世界杯无法结束
- 合同 / 转会流程死锁
- 严重数据重复 / 丢失
- 手机端核心按钮无法操作
- 页面大面积横向溢出
- JS 语法错误
- 浏览器原生 alert / confirm 泄漏到正式体验
- 关键年份进入错误赛制
- 退役后无法结算

## P1 · High
可以进入内测，但不应进入稳定公开版：

- 奖项明显保送
- 英雄选择长期失真
- 地图池错误
- 国家队磨合明显不合理
- 数据口径错误
- 合同角色与实际出场严重不符
- 季后赛结果展示错误
- 重要按钮位置错乱
- 长档 AI 生态崩坏
- 明显性能卡顿

## P2 · UX / Polish
不阻塞功能测试，但应尽快处理：

- 文案
- 字号
- 留白
- 卡片排序
- 轻微颜色对比
- 次要动画
- 非核心信息层级

# 1. 发布门禁总流程

每个候选版本至少执行：

1. **静态构建检查**
2. **新档 Smoke Test**
3. **2019～2023 历史赛制回归**
4. **2024+ OWCS 回归**
5. **完整赛季回归**
6. **世界杯回归**
7. **合同 / 转会回归**
8. **英雄训练 / 英雄选择回归**
9. **奖项回归**
10. **存档 / 读档回归**
11. **退役回归**
12. **390px 手机端回归**
13. **6～10 年长档**
14. 重大底层改动后追加 **15 年极限长档**
15. **GitHub dev / Cloudflare dev 发布一致性**

发布一致性至少核对：本地候选提交、GitHub `dev`、Cloudflare dev 实际资源和线上版本号。

# 2. A 类 · 构建与基础 Smoke

## A-01 HTML 可打开
**步骤**
1. 打开当前 `dev-public/dev/index.html`，并在发布后打开线上 `/dev/`。
2. 进入主菜单。

**预期**
- 页面正常加载。
- 无白屏。
- 无 JS 初始化异常。
- 版本号正确。

---

## A-02 JavaScript 语法
**预期**
- 所有 script 块语法检查通过。
- 不允许出现未闭合模板字符串、重复声明、非法 await 等问题。

---

## A-03 浏览器原生弹窗
**检查**
- 开档
- 季后赛
- 世界杯
- 训练
- 转会
- 退役
- 存档覆盖 / 删除 / 清空

**预期**
- 不出现浏览器原生 `alert / confirm / prompt`。
- 全部使用游戏内 UI。

---

## A-04 新建角色完整链
**流程**
位置 → 队伍抽签 → 队员抽签 → 属性模板 → 名称 / 国籍 / 年龄 → 首发名单。

**预期**
- 每一步都可返回 / 继续。
- 重 roll 次数正确。
- 最终角色信息完整。
- 第一个角色不开放位置训练。

---

## A-05 发布资源一致性

**步骤**
1. 在 `dev` 分支提交并推送候选版本。
2. 通过开发部署脚本发布 Cloudflare dev。
3. 直接请求 `/dev/`、Shared Runtime 和至少一个本轮改动的 patch 资源。

**预期**
- GitHub `dev`、本地候选版本、Cloudflare dev 版本可对应到同一个提交。
- HTML、CSS、JS 资源返回 200。
- 线上资源包含当前版本的 Shared Runtime / patch 标记，不是旧缓存或旧 RC 资源。
- Wrangler OAuth 或 API token 任一授权路径均可完成发布；失败时不得假报成功。

# 22. QA 执行原则

1. **不要只测“这次改的按钮”。**
   - 改地图池，就要测详细比赛、Hero Ban、世界杯、存档。
   - 改赛季推进，就要测 Stage、Major、Final、世界杯时间线。
   - 改奖项，就要测退役总结和生涯荣誉。

2. **同类 Bug 第二次出现，永久进入回归列表。**

3. **移动端不是发布后再看。**
   - 390px 必须是发布门禁。

4. **完整赛季和手动推进都要测。**
   - 两条路径经常不是同一套代码。

5. **快速模拟和详细模拟必须结果兼容。**
   - 可以过程简化，不能规则不同。

6. **旧 QA 断言如果已经被产品规则淘汰，应更新测试，不要为了“绿”硬保留旧规则。**

7. **任何“看起来通过”的结果，都要核对数据链。**
   - UI 显示冠军不够，要看 bracket / history / career record 是否一致。

8. **不允许用玩家身份做隐藏保送。**
   - MVP、Dennis、国家队、首发、转会都必须存在 AI 竞争。

9. **长档是核心 QA，不是额外彩蛋。**
   - 这个项目最危险的 Bug，大部分都不会在第一年出现。

10. **最终稳定版的标准不是“没报错”，而是“玩 6～10 年后世界仍然像个职业联赛”。**

# 手机网页游戏 UI / 分辨率适配规范

> 适用范围：竖屏手机网页游戏  
> 核心原则：不要按设备物理分辨率逐个适配，而是按 **CSS Viewport 宽度 + 屏幕比例** 做响应式适配。

---

## 1. 基础原则

项目以 **竖屏手机网页游戏** 为主要使用场景。

统一采用：

- **手机设计基准：390 × 844**
- **平板设计参考：768 × 1024**

这里的尺寸均指 **CSS Viewport 逻辑尺寸**，不是手机实际的 `1080×2400`、`1179×2556` 等物理分辨率。

UI 不针对具体手机型号单独适配。

---

## 2. 适配范围与优先级

| 类型 | CSS Viewport 宽度 | 优先级 | 处理方式 |
|---|---:|---|---|
| 极小手机 | 320～359 | P2 | 保底可用，不要求最佳体验 |
| 主流手机 | **360～430** | **P0** | 完整适配 |
| 大屏手机 / 折叠屏 | 431～599 | P1 | 延续手机版布局，限制内容宽度 |
| 平板 | **600～1024** | **P1** | 平板适配 |
| PC / 大屏 | 1025+ | P2 | 居中显示，限制最大内容宽度 |

### P0 手机重点测试

必须保证：

- `360 × 800`
- `375 × 812`
- `390 × 844`
- `393 × 852`
- `412 × 915`
- `430 × 932`

其中：

> **390 × 844 = UI 主要设计基准**

额外做一次极限测试：

- `360 × 640`

要求至少：

- 不溢出
- 不重叠
- 按钮可操作
- 弹窗可完整使用
- 允许局部滚动

---

## 3. 手机屏幕比例

至少兼容：

- `16:9`
- `18:9`
- `19.5:9`
- `20:9`
- `21:9`

原则：

> **宽度决定主要布局，屏幕高度差通过留白、背景和内容区域消化。**

不能因为屏幕变长，就把所有 UI 一起放大。

例如：

```text
390 × 844
↓
390 × 900
```

应该表现为：

> 上下可用空间增加

而不是：

> 所有按钮、头像、文字全部同比放大。

---

## 4. 平板适配

平板重点测试：

- `768 × 1024`
- `810 × 1080`
- `820 × 1180`
- `834 × 1194`
- `1024 × 1366`

### 平板原则

#### 方案 A：普通界面

可以继续沿用手机版逻辑，但：

> **主体区域设置最大宽度并居中，两侧使用背景补充。**

示意：

```text
┌───────────────────────────┐
│      背景   主体   背景    │
│             UI             │
│             UI             │
│             UI             │
└───────────────────────────┘
```

不要把手机版 UI 从 390 直接暴力拉到 1024。

#### 方案 B：信息量大的界面

例如：

- 背包
- 神将
- 装备
- 阵容
- 排行榜
- 商店
- 角色详情

手机版：

```text
角色
↓
属性
↓
装备
↓
操作
```

平板：

```text
角色 + 属性    装备 / 详情
```

即：

> **手机纵向堆叠，平板允许双栏。**

不强制所有页面都重新设计 Tablet Layout，优先处理信息密集页面。

---

## 5. UI 设计要求

UI 统一以：

> **390 × 844**

作为设计稿基准。

### 横向

核心内容建议控制在：

- `360～430`

范围内均能正常显示。

不要写死：

```text
固定 390 宽
```

而应该理解为：

```text
390 是设计基准
360 可以压缩
430 可以舒展
```

### 纵向

重要按钮不要依赖固定 Y 坐标。

例如不要设计成：

> 按钮永远距离页面顶部 760px

应该采用：

- 顶部区域
- 内容区域自适应
- 底部操作区域

这样 `800` 高、`844` 高、`932` 高都能正常工作。

---

## 6. 安全区

必须适配：

- 刘海
- 灵动岛
- 圆角屏
- Android 打孔屏
- iPhone Home Indicator
- 横屏刘海

程序需支持：

```css
env(safe-area-inset-top)
env(safe-area-inset-bottom)
env(safe-area-inset-left)
env(safe-area-inset-right)
```

底部核心按钮尤其不能贴死屏幕底边。

建议：

```text
屏幕底部
↓
系统安全区
↓
额外 UI 间距
↓
操作按钮
```

---

## 7. 页面高度

程序尽量使用：

```css
100dvh
```

而不是只使用：

```css
100vh
```

因为手机浏览器的：

- 地址栏
- 底部工具栏
- 全屏 / 非全屏

都会导致传统 `100vh` 出现高度问题。

---

## 8. 弹窗规范

弹窗是最容易出现适配问题的区域，统一要求如下。

### 宽度

手机版：

> 不超过屏幕宽度 - 安全边距

例如：

```css
width: calc(100vw - 32px);
max-width: 390px;
```

### 高度

弹窗不能超出当前可视区域。

内容过长时：

> **弹窗本身固定在屏幕内，内容区滚动。**

不要让：

```text
确认按钮
```

跑到屏幕下面。

---

## 9. 字体与按钮

不要随分辨率无限缩放。

### 字体

以设计稿字号为基准，通过有限档位调整。

例如：

- 360 宽：略微缩小
- 390 宽：标准
- 430 宽：基本保持
- 平板：视界面适当增加

### 点击区域

手机按钮实际可点击区域建议：

> **至少约 44 × 44 CSS px**

图标本身可以小，但点击热区不要太小。

---

## 10. 响应式断点建议

程序可以先按下面三档处理：

```css
/* 手机 */
@media (max-width: 599px) {

}

/* 平板 */
@media (min-width: 600px) and (max-width: 1024px) {

}

/* PC / 大屏 */
@media (min-width: 1025px) {

}
```

手机内部不要再针对：

- iPhone 14
- iPhone 15
- 小米
- OPPO
- vivo
- 三星

一台一台写。

主要依靠：

```text
flex
grid
百分比
min / max
clamp()
safe-area
```

处理。

---

## 11. 最终验收标准

### P0 手机

必须测试：

| Viewport | 要求 |
|---|---|
| 360 × 640 | 极限保底 |
| 360 × 800 | 安卓小屏 |
| 375 × 812 | iPhone 经典 |
| **390 × 844** | **主基准** |
| 393 × 852 | 主流 iPhone |
| 412 × 915 | 大屏安卓 |
| 430 × 932 | 大屏 iPhone |

要求：

- 无文字溢出
- 无按钮重叠
- 无内容被刘海遮挡
- 无底部按钮被系统区域遮挡
- 弹窗全部可操作
- 长内容允许滚动
- 图片不变形
- 背景可以裁切 / 延展

### P1 平板

测试：

- `768 × 1024`
- `820 × 1180`
- `834 × 1194`
- `1024 × 1366`

要求：

- 手机版界面不能被粗暴拉宽
- 主体可限制最大宽度并居中
- 信息密集页面允许双栏
- 两侧多余空间使用背景填充

---

## 12. 精简口径

> 项目以竖屏手机网页为主，UI 设计基准采用 **390 × 844 CSS Viewport**；P0 完整适配 **360～430** 宽度及 **16:9～21:9** 屏幕比例，`360 × 640` 作为极限保底。P1 兼容 **600～1024** 宽度平板，平板不得直接拉伸手机版 UI，普通页面可限制主体最大宽度居中，信息密集页面允许双栏布局。1024 以上大屏采用居中 + 最大宽度限制。所有页面需支持 **Safe Area、100dvh**，弹窗不得超出可视区域，长内容内部滚动。

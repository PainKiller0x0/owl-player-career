# PC 网页端 UI / 分辨率适配规范

> 适用范围：PC 浏览器网页游戏  
> 核心原则：PC 端按 **CSS Viewport（浏览器可视区域）** 做响应式适配，不按显示器物理分辨率写死布局。

---

## 1. 基础原则

PC 网页端与手机 / 平板端分开设计和适配。

PC 端统一采用：

- **主设计基准：1440 × 900 CSS Viewport**
- **P0 最小完整支持：1280 × 720**
- **推荐核心游戏内容最大宽度：1440～1600 CSS px**
- 1920、2K、超宽屏增加的空间优先用于 **背景、场景、装饰、留白**，不要无限拉伸核心 UI。

这里的尺寸均指浏览器网页实际可用的 **CSS Viewport**，不是显示器标称的 `1920×1080`、`2560×1440`。

例如：

```text
显示器：1920 × 1080
Windows 缩放：125%
浏览器未全屏
```

最终网页拿到的可视区域可能远小于 `1920 × 1080`。

因此程序禁止根据显示器型号或物理像素直接判断布局。

---

## 2. 适配范围与优先级

| 类型 | CSS Viewport 宽度 | 优先级 | 处理方式 |
|---|---:|---|---|
| 紧凑 PC 窗口 | 1025～1279 | P1 | 压缩布局 / 部分区域滚动 |
| 标准 PC | **1280～1919** | **P0** | 完整适配 |
| 大屏 PC | **1920～2559** | **P0** | 核心区限制最大宽度 |
| 2K / 高分屏 | 2560～3439 | P1 | 核心区居中，扩展背景 |
| 超宽屏 | 3440+ | P1 / P2 | 不铺满 UI，使用背景消化额外空间 |

### PC 端重点测试尺寸

P0 必须测试：

- `1280 × 720`
- `1366 × 768`
- `1440 × 900`
- `1536 × 864`
- `1920 × 1080`

P1 建议测试：

- `2560 × 1440`
- `3440 × 1440`

其中：

> **1440 × 900 = PC 端 UI 主要设计基准**

---

## 3. 核心内容区规则

PC 屏幕越宽，不代表游戏 UI 也要一直变宽。

建议核心内容区：

```css
.game-main {
    width: 100%;
    max-width: 1600px;
    margin: 0 auto;
}
```

具体页面可以根据实际设计在 `1440～1600px` 范围内确定最大宽度。

### 正确方式

```text
┌────────────────────────────────────────────┐
│                背景 / 场景                 │
│      ┌────────────────────────────┐        │
│      │        核心游戏 UI          │        │
│      │       1440～1600宽          │        │
│      └────────────────────────────┘        │
│                背景 / 场景                 │
└────────────────────────────────────────────┘
```

### 禁止方式

屏幕从：

```text
1440 → 1920 → 2560 → 3440
```

时，不要同步出现：

- 按钮无限变宽
- 列表无限变宽
- 弹窗无限变宽
- 角色立绘被横向拉伸
- 左右信息相距过远
- UI 元素失去视觉聚合

---

## 4. 页面高度与窗口化适配

PC 玩家不一定全屏运行游戏。

常见情况：

```text
1920 × 1080 显示器
↓
浏览器窗口只打开 1400 × 820
```

因此布局必须根据当前浏览器可视区域响应。

### 高度原则

建议优先使用：

```css
min-height: 100dvh;
```

关键页面不能依赖固定高度，例如：

```text
按钮固定在 top: 820px
```

应采用：

- 顶部导航区
- 主内容自适应区
- 底部操作区

### 页面高度不足时

优先级：

1. 保证核心操作按钮始终可用
2. 次要信息允许滚动
3. 装饰性内容允许裁切
4. 禁止通过整体无限缩小 UI 来硬塞

---

## 5. 页面布局规则

### 普通页面

如：

- 首页
- 活动页
- 充值页
- 商城页
- 简单玩法页

建议采用：

> **居中核心区 + 两侧背景扩展**

### 信息密集页面

如：

- 背包
- 神将
- 装备
- 阵容
- 排行榜
- 角色详情
- 商店列表
- 养成界面

PC 应充分利用横向空间，可采用：

```text
┌──────────┬─────────────────┐
│ 左侧导航  │    主内容区      │
│ /角色列表 │                 │
│          │                 │
└──────────┴─────────────────┘
```

或：

```text
┌─────────────┬─────────────┐
│ 角色 / 列表  │ 属性 / 详情  │
└─────────────┴─────────────┘
```

原则：

> **PC 优先横向分栏，不要简单把手机纵向页面放大。**

---

## 6. 弹窗规范

弹窗必须适配不同窗口尺寸。

### 宽度

建议：

```css
.modal {
    width: calc(100vw - 48px);
    max-width: 900px;
}
```

具体最大宽度按弹窗类型确定。

不建议普通弹窗铺满整个 PC 页面。

### 高度

弹窗最高不能超过当前可视区域。

建议：

```css
.modal {
    max-height: calc(100dvh - 48px);
}
```

长内容采用：

> **标题固定 + 内容区滚动 + 底部操作区固定**

禁止：

- 确认按钮跑出屏幕
- 关闭按钮不可见
- 弹窗整体超过浏览器窗口
- 为塞内容而把所有字体缩得过小

---

## 7. 浏览器缩放兼容

PC 用户经常使用浏览器缩放。

至少测试：

- `90%`
- `100%`
- `110%`
- `125%`

要求：

- 不出现明显重叠
- 不出现文字被裁切
- 核心按钮仍可操作
- 弹窗仍能完整使用
- 列表 / 表格允许合理换行或滚动

程序不能把 `100%` 浏览器缩放视为唯一情况。

---

## 8. Windows 系统缩放 / 高 DPI

常见 Windows 缩放：

- `100%`
- `125%`
- `150%`

程序仍以浏览器提供的 CSS Viewport 为准。

UI 素材需要考虑高 DPI 场景，避免：

- 图标模糊
- 文字贴图模糊
- 背景图放大后失真

建议：

- 常规 UI 图片优先准备高分辨率源图
- 位图素材建议至少满足 @2x 使用需求
- CSS 中按照逻辑尺寸显示
- 不要为了高清屏直接把 UI 逻辑尺寸放大一倍

---

## 9. 鼠标交互规范

PC 端需要正式支持鼠标操作。

### 必须支持

- Hover 高亮
- 鼠标点击状态
- 鼠标滚轮
- Tooltip / 悬浮信息
- 可点击区域有明确反馈

### 建议支持

- 当前选中状态
- 禁用状态
- 按下状态
- 键盘焦点状态（涉及输入框时）

### 不建议依赖

- 右键作为关键操作
- 双击作为唯一核心操作
- 鼠标悬浮才能获取必须信息

Hover 可以增强体验，但关键功能不能只有 Hover 才能发现。

---

## 10. 滚动区域规范

PC 信息量通常大于手机端，滚动区域需要明确。

建议：

- 页面整体尽量避免多层嵌套滚动
- 列表区可以独立滚动
- 弹窗内容可以独立滚动
- 鼠标滚轮进入某区域后应有明确行为
- 滚动条不应遮挡关键按钮或内容

列表非常长时，优先采用：

- 分页
- 虚拟列表
- 固定表头
- 独立内容滚动区

---

## 11. 字体规范

PC 不要因为屏幕变大就同步无限放大字体。

原则：

- `1440 × 900` 使用标准设计字号
- `1280 × 720` 可做有限压缩
- `1920 × 1080` 基本保持标准字号
- 2K / 超宽屏不直接按比例放大字体

文字区域必须允许：

- 合理换行
- 超长内容省略
- Tooltip 查看完整内容（适用于辅助信息）

禁止因固定宽度导致文本直接溢出 UI。

---

## 12. 图片 / 背景适配

### UI 图片

禁止非等比拉伸。

使用：

```css
object-fit: contain;
```

或根据需求使用：

```css
object-fit: cover;
```

### 背景图片

PC 背景需要考虑：

- 16:9
- 16:10
- 21:9
- 超宽屏

建议背景重点内容集中在中心安全区域。

左右两侧允许：

- 延展
- 裁切
- 雾化
- 重复纹理
- 场景装饰填充

核心人物 / Logo / 关键文字不要放在极端边缘。

---

## 13. 超宽屏规则

对于：

- `2560 × 1080`
- `3440 × 1440`
- 32:9 等更宽屏幕

原则：

> **核心游戏 UI 不随屏幕无限拉伸。**

推荐：

```text
超宽背景
┌───────────────────────────────────────────────┐
│        ┌─────────────────────────────┐        │
│        │         核心游戏区           │        │
│        │        1440～1600宽          │        │
│        └─────────────────────────────┘        │
└───────────────────────────────────────────────┘
```

超出核心区的部分主要承担视觉氛围，不承载关键操作。

---

## 14. PC 响应式断点建议

建议：

```css
/* 紧凑 PC / 小窗口 */
@media (min-width: 1025px) and (max-width: 1279px) {

}

/* 标准 PC */
@media (min-width: 1280px) and (max-width: 1919px) {

}

/* 大屏 PC */
@media (min-width: 1920px) and (max-width: 2559px) {

}

/* 2K / 超宽屏 */
@media (min-width: 2560px) {

}
```

不要针对具体显示器品牌、显卡、设备型号单独适配。

主要依赖：

```text
flex
grid
百分比
min()
max()
clamp()
max-width
min-width
dvh
```

进行响应式处理。

---

## 15. PC 与移动端切换边界

项目已有手机 / 平板端规范。

建议平台边界统一为：

```text
≤ 1024px
移动 / 平板规范

≥ 1025px
PC 网页端规范
```

注意：

> 这里仍然是 CSS Viewport 宽度，而不是物理屏幕宽度。

当用户缩小 PC 浏览器窗口时，可以进入“紧凑 PC”布局，而不是强行保持大屏布局。

---

## 16. 最终验收标准

### P0 必测尺寸

| Viewport | 用途 |
|---|---|
| **1280 × 720** | PC 最小完整支持 |
| **1366 × 768** | 常见笔记本 |
| **1440 × 900** | **主设计基准** |
| **1536 × 864** | 高 DPI / 常见实际 Viewport |
| **1920 × 1080** | 主流桌面屏 |

### P1 建议测试

| Viewport | 用途 |
|---|---|
| 2560 × 1440 | 2K |
| 3440 × 1440 | 21:9 超宽屏 |

### 必须满足

- 无文字溢出
- 无 UI 重叠
- 无图片非等比拉伸
- 核心游戏区不会无限拉宽
- 弹窗不会超出浏览器可视区域
- 长内容可正常滚动
- 鼠标 Hover / 点击状态正常
- 滚轮行为正常
- 浏览器 90%～125% 缩放可正常使用
- Windows 125% / 150% 缩放下无明显异常
- 1280 × 720 下核心功能完整可操作
- 2K / 超宽屏下不会出现大片失控拉伸 UI
- 浏览器窗口化时布局能够正常响应

---

## 17. 给 UI / 程序的简版同步口径

> PC 网页端以 **1440 × 900 CSS Viewport** 作为 UI 主设计基准，P0 完整适配 `1280 × 720`、`1366 × 768`、`1440 × 900`、`1536 × 864`、`1920 × 1080`，P1 兼容 2K 与 21:9 超宽屏。核心游戏内容建议限制在 **1440～1600px 最大宽度**并居中，屏幕增加的额外空间使用背景 / 场景延展，不允许整体 UI 无限横向拉伸。PC 端需支持窗口化、浏览器 `90%～125%` 缩放、Windows 高 DPI、鼠标 Hover / 滚轮 / Tooltip。弹窗不得超出 `100dvh` 可视区域，长内容内部滚动。CSS Viewport `≥1025px` 进入 PC 端适配规范，`≤1024px` 按移动 / 平板规范处理。
